About

Background, focus areas, and working principles.

Jorge Aquino

Background

I served as a Marine and then as a Firefighter/EMT. I now work as a software engineer and do independent application security research outside that role.

I'm a member of the OWASP Foundation, and the OWASP Top 10 and API Security Top 10 cover most of what I'm interested in, from injection and authentication failures to misconfiguration, server-side request forgery, and supply chain risks.

Broken access control is where I spend the most time. It's #1 in the OWASP Top 10:2025, and three of the top five risks in the 2023 API list concern authorization at the object, property, or function level. Most of the tools below are aimed at it.

I came into software engineering without a computer science degree. Students and career changers are welcome to send questions through the contact page.

What I work on

Authorization bugs are easy to miss. The request succeeds and the response looks normal; the defect is that the wrong user received the data. Scanners have trouble finding them because the access rules usually aren't written down anywhere a tool can read.

I build open-source tools for this:

  • VardrGate: access rules are rarely written down, so nothing checks them. VardrGate tests a policy file against live API responses and can run in CI.
  • VardrMap: an engagement tracker that keeps scope, assets, evidence, and findings in one place, so test coverage is recorded rather than remembered.
  • VardrRunner: runs scan jobs on your own machine and uploads results to the backend.
  • VardrForge, still in design: the goal is to generate small testing tools with a target allowlist.

The checklists on this site can be copied into tickets and code-review templates.

How I work

  • I only test with written authorization and an agreed scope.
  • Every finding I report comes with evidence you can reproduce, or is clearly marked as uncertain.
  • Response times are not guaranteed, and I do not provide emergency incident response.
