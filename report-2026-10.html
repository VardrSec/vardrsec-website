October 2026: establishing the research baseline

A first look at the evidence collected by the VardrSec SSH sensor, and the standards that will govern monthly reporting.

Working draft — partial month. October is still in progress. The figures below describe an already-public snapshot, not full-month totals. No threat actor attribution or confirmed malware-family claim is made.
Download draft PDF Technical artifacts on GitHub

This reference snapshot was published at 2026-10-15T02:00:09Z. Activity covers 2026-10-14T01:00:00Z to 2026-10-15T01:00:00Z (end exclusive). It is deliberately delayed and does not expose individual source addresses.

These counts measure events at one SSH decoy. A login accepted by the honeypot is not evidence of access to the host. File-transfer events do not establish that a captured file is malware. Source counts do not identify distinct people or campaigns.

Selected command patterns: a seven-day window

Command reporting covers 2026-10-08T01:00:00Z to 2026-10-15T01:00:00Z (end exclusive). Templates replace keys, arbitrary arguments, paths, and destinations with fixed markers; unsupported syntax is omitted.

cd ~ ; chattr -ia .ssh ; [EXECUTABLE] -ia .ssh

150 normalized command occurrences in the seven-day window.

cd ~ && rm -rf .ssh && mkdir .ssh && echo [SSH_KEY] >> .ssh/authorized_keys && chmod -R go= ~/.ssh && cd ~

146 normalized command occurrences in the seven-day window.

The authorized-keys pattern expresses an attempt to prepare an SSH directory and add a key. The attribute-change pattern includes a redacted executable, so the template alone cannot establish that executable's identity or intent. Counts combine normalized inputs and do not prove that any action succeeded.

Interpretation and TTP context

SSH authorized-key modification is consistent with the behavior described in MITRE ATT&CK T1098.004. This is a behavioral mapping, not attribution. The sensor's emulated environment and selective command grammar limit what can be concluded.

MITRE ATT&CK T1105 provides context for tool-transfer attempts in future analysis. It is reference material, not evidence that this draft identified a particular transfer campaign. External campaign research and emerging-threat assessments remain pending for the monthly close.

Malware analysis and IOCs

No captured sample or unreviewed hash is published with this draft. Static triage uses cryptographic hashes, file signatures, and bounded heuristic rules in an isolated environment. A match is an observation for investigation, not a malware verdict. Human conclusions are kept separately from automated observations.

The reviewed YARA triage rules are available as a technical artifact. The rules contain no captured payload. Public IOCs will require evidence, context, confidence, and review before release.

How monthly reporting will be completed

Detailed telemetry has a 30-day retention policy. Incremental private archival preserves calendar-month counts before records expire, including late imports and deduplicated reimports. Captured samples remain outside automatic deletion. Monthly distinct counts are computed over the month, not by adding daily unique counts.

At month close, review collection gaps, freeze the report revision, analyze representative evidence, approve any IOCs, and add dated primary-source research. The report will distinguish original observations, analyst inference, externally reported findings, and unresolved questions.

Methods, limitations, and corrections

One sensor and one protocol cannot measure global threat prevalence. The first and last recorded observations do not prove continuous uptime. The command table is intentionally selective. A partial month does not support a monthly trend comparison.

Review the methodology and frozen public snapshot. Follow the Threat Observatory for current delayed observations. Send corrections to contact@vardrsec.com.
