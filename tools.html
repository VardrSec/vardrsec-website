Tools

Security tooling I build and maintain. The published ones are open source—read the code, run it, break it, tell me what's wrong with it.

A common thread: most of this exists because broken access control keeps winning. It is the vulnerability class I find most often, the hardest to catch with a scanner, and the one that does the most damage when it slips through. Nearly every tool here is an attempt to make it cheaper to find before someone else does.

Published

Open source, MIT-spirited, and usable today.

Go Open source

VardrGate

Continuous API authorization assurance. You describe how an endpoint should treat different callers—who may read, who may write, who should be refused outright—then VardrGate runs the same request as each of them and reports, with evidence, wherever the real behaviour disagrees with the intent.

It exists because authorization bugs do not look like bugs. The endpoint returns 200. The response is well-formed. Nothing crashes. The only thing wrong is who got the data, and no scanner knows what your rules were supposed to be. So you have to write them down—and once they are written down, they can be tested on every commit.

VardrMap

An attack surface mapping and threat-modelling workspace. Organise targets, record what you think is true about them, track which hypotheses you have actually tested, and pull in reconnaissance and enrichment data without leaving the workspace.

Built out of frustration with the real state of most assessments: findings in one document, scope in an email, recon output in twelve terminal scrollbacks, and no honest answer to "what have I actually looked at?" VardrMap makes that question answerable.

Python Open source

VardrRunner

The local automation runner for the rest of the toolchain. It polls a backend for queued scan jobs, claims them atomically, executes the tool on your machine, streams progress back, and uploads results.

The design principle is deliberate: recon and scanning belong on the operator's box—their bandwidth, their IP, their tool versions, their legal footing. The backend orchestrates and stores; the runner does the work. The two are fully decoupled and only ever exchange JSON. No vendor ever needs to hold your credentials or scan from their infrastructure.

VardrForge

A local CLI that generates small, modular pen-testing tools from controlled templates—with scope validation baked in. Every generated tool is restricted to an explicit target allowlist, so it cannot be pointed somewhere it was never authorised to go.

Go

VardrVault

A secrets manager with token auth, encrypted storage, and audit logging. Built mostly to understand the problem properly—you learn a great deal about a threat model by having to implement against it.
